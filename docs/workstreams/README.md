# Workstream Briefs (P1–P6)

Parallel workstream specifications for the Nomi MVP. Each brief repeats the
shared project context, then defines one workstream's ownership, deliverables,
coordination points, and finish line.

| Brief | Scope |
| --- | --- |
| [P1 — Anomaly Detection + Detection API](p1-anomaly-detection.md) | Sudden behavioural anomaly detection on top of the personal baseline; explainable detection service/API. |
| [P2 — Longitudinal Change Detection + Evaluation](P2/p2-change-detection-evaluation.md) | Gradual/sustained change detection; synthetic senior scenarios; prototype evaluation of the combined approach. |
| [P3 — Messaging + Check-In Pipeline](p3-whatsapp-integration.md) | Provider-based check-ins and webhooks. Telegram Bot API is the live proof-of-concept transport; the WhatsApp Cloud API material is retained as future-provider reference. Reference folder: [P3/](P3/) ([Telegram demo setup](P3/telegram-demo-setup.md), [presentation demo](P3/presentation-demo.md), [session scoring](P3/session-scoring.md), [WhatsApp reference](P3/meta-cloud-api-setup.md)). |
| [P4 — Verification + Escalation + Caregiver Alert Engine](p4-verification-escalation.md) | Decision layer between detection and caregiver action; senior-first verification; deterministic escalation rules. |
| [P5 — Frontend + Product / Demo UX](p5-frontend-product-ux.md) | Judge-facing caregiver experience; baseline, trend, detection, verification, and alert views. |
| [P6 — Integration + Deployment + End-to-End QA](p6-integration-deployment-qa.md) | Wire the workstreams into one deployed MVP; deterministic demo scenario; end-to-end QA and demo resilience. |
